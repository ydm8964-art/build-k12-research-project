# 26项材料固定版式合同

本文件是[`material-format-contracts.json`](material-format-contracts.json)的人工可读说明。JSON是生成和机器审计的唯一执行源；本文件用于核对。除当年官方原模板或用户明确指定的同类模板外，不得临时改变字体、字号、缩进、行距、页边距或表格规则。

## 一、权威与例外

1. `M01/M02/M03/M22`采用`official-template-exact`：字体字号、段落、表格、页面、页眉页脚、域、图片和签章区全部继承实际参考模板，禁止套用通用字号；未取得参考模板时阻断制作可提交稿。
2. 其余DOCX均采用下表绑定的固定合同。若当年通知另有明确要求，先把新要求写入合同并留存来源，再重新生成和审计；不得只在Word中手工改一处。
3. `M09`采用固定XLSX工作簿合同，详细规则见下文和[spreadsheet-standards.md](spreadsheet-standards.md)。

## 六、Word表格统一硬值

- 固定布局，表格缩进0 DXA；明确总宽、列宽网格和单元格宽度，不允许自动伸缩造成跨软件漂移。
- 单元格上/下内边距100 DXA，左/右内边距120 DXA；首行跨页重复，所有单元格垂直居中。
- 表头宋体10.5磅（横向控制表为9磅）、加粗、水平居中；表内正文宋体10.5磅（横向控制表为9磅）、不加粗、零首行缩进。
- 禁止固定行高；内容自然增高。合并、列宽和边框按材料语义预设，最终必须逐页检查越界、截字和空白页。

## 七、M09电子工作簿固定值

- 9张工作表及顺序固定为：项目说明、变量编码、原始数据、清理编码、统计分析、图表结果、证据索引、照片登记、材料进度；不得保留默认空白表。
- 全簿字体固定为Microsoft YaHei。标题14磅白色加粗、深蓝底；说明行10磅深色、浅蓝底；表头11磅白色加粗、深蓝底；输入/公式区11磅，分别使用浅黄/浅绿底。
- 标题、说明、表头、数据行高依次为26、52、28、24磅；第3行以下冻结，活动单元格A4；关闭网格线。
- 每张工作表的列宽由母版逐列固定；数据区为第4—33行预留区，启用筛选和必要的数据验证，禁止合并单元格。
- 日期`yyyy-mm-dd`、计数`#,##0`、比例`0.0%`、得分`0.00`；数字、日期和百分比必须保留真实类型，不能保存为显示字符串。
- 所有生成或填充后的工作簿必须与`assets/templates/project-data-workbook.xlsx`比较样式表、列宽、冻结窗格、首3行及预留数据区样式；只允许值、公式和按同一角色扩展的数据行发生变化。

## 八、强制执行顺序

```bash
python scripts/resolve_material_format.py --material-id M21 --validate-catalog --out M21-format.json
python scripts/apply_docx_format_contract.py draft.docx --material-id M21 --out formatted.docx
python scripts/audit_docx_style_contract.py formatted.docx --material-id M21
python scripts/audit_docx_format.py formatted.docx --profile analysis-report --final
python scripts/audit_xlsx_style_contract.py M09.xlsx
```

`official-template-exact`不运行通用套版脚本，改为同时向两个审计脚本提供`--reference official-template.docx`。任何字体、字号、首行缩进、行距、页边距或表格硬值错误都不能标记`ready`。

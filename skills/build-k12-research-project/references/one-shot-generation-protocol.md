# 一次性成套生成协议

本协议解决“确认题目后，一次生成整套材料”的范围、输入、顺序和真实性边界。

## 目录

1. 四种成套范围
2. 一次采集的信息包
3. 完整生命周期配方
4. 单批次生成顺序
5. 可用状态的准确含义

## 一、四种成套范围

| 范围 | 一次生成的含义 | 可以达到的状态 |
|---|---|---|
| `application-kit` | 当年申请书、匿名活页及申报附件 | 官方要求已核验后可形成报送稿；签章仍由真人完成 |
| `implementation-kit` | 开题、实施方案、工具、记录表、数据工作簿、策略、课例/任务单/量规、过程台账 | 可直接执行和填写；结果区不预造数据 |
| `full-lifecycle-kit` | 申请＋实施＋中期＋结题的全部文件和模板在同一批次生成 | 申报/实施材料可用；分析、效果、结题文件在真实证据进入前保持`pending-data/photo/signature` |
| `closing-kit` | 根据已完成项目的真实数据、记录、照片和成果生成研究报告及结题包 | 证据齐全、官方模板核验并完成审计后才可提交 |

“一次性生成全套”不等于在申报当天伪造未来结果。没有真实数据、照片、专家意见、单位意见、签字或盖章时，生成的是结构完整、彼此一致、可直接实施的文件和待填台账；结果型终稿只能在真实材料到位后批量刷新。

## 二、一次采集的信息包

题目确认前后集中收集一次，后续不重复询问已经登记的字段：

1. 身份：负责人、学校全称、地区、职称职务、联系方式、成员及排序；
2. 教学：学段、主学科、实际关联学科、教材版本、年级班级、人数、课时和校情；
3. 问题：具体表现、已有证据、原因假设、已有做法和资源；
4. 申报：年份、级别、管理单位、周期、通知、官方模板、匿名和签章要求；
5. 研究：对象、样本边界、核心策略、可用工具、预期成果和实施场景；
6. 真实性状态：哪些调查、课例、活动、照片、成果已真实发生，哪些只是计划；
7. 交付：需要的成套范围、版本、文件格式、是否需要PDF和打印要求。

未知事实只登记一次并进入“待补字段表”。身份、申报资格、研究对象、周期或官方模板这类会改变整套结果的字段缺失时阻断正式生成；照片、实际样本、结果等未来事实不阻断`full-lifecycle-kit`，但对应材料自动进入待数据/待照片状态。

## 三、完整生命周期配方

### 1. 申报与立项

- 当年通知、指南、官方表格和要求快照；
- 申请书/申报书、匿名活页、负责人承诺；
- 成员与前期成果证明索引、学校推荐/汇总材料（按通知）；
- 立项通知和项目编号登记。

### 2. 开题与实施准备

- 开题报告、详细实施方案、成员分工和甘特式进度表；
- 专家/与会人员/单位意见空白区，不代填真实意见；
- 研究伦理和告知同意材料、数据管理方案；
- 研究问题—维度—指标—题号—分析矩阵。

### 3. 工具与原始记录

- 所选方法对应的问卷、访谈、观察、测评/作品评价工具；
- 每种工具的空白版、记录版、变量编码/编码本和使用说明；
- 预测试记录、工具修订记录、样本流转表；
- XLSX数据工作簿、访谈转写/编码表、观察汇总表；
- 照片拍摄任务清单、照片登记、活动记录、授权状态和证据索引；每个计划插图位置预先分配照片ID、活动、日期窗口、拍摄内容、授权要求和目标材料。

### 4. 诊断、干预和课堂实践

- 各工具分析报告及三角互证总表；
- 诊断问题—对应策略—实施载体—评价—证据矩阵；
- 干预/教学策略框架、教学设计基本框架；
- 常态课或示范课教学设计、任务单、学习支架、量规和反思表；
- 案例稿、案例状态、实施保真度和改进记录。

### 5. 过程管理

- 教研会议、培训、集体备课、课堂实施和推广应用记录；
- 阶段总结、中期报告、问题清单和下一步计划；
- 题目、成员、周期、成果等变更材料；
- 代表性真实照片证据册和受控原件索引。

### 6. 成果与结题

- 最终研究报告/研究总报告；
- 案例集、资源包、论文或其他承诺成果；
- 结题申请/鉴定书、成果目录、成果摘要；
- 发表、获奖、应用、推广和社会反响证明索引；
- 承诺成果核销表、研究局限、变更说明、数据和照片附录；
- 整套材料目录、预检报告和待签章事项。

## 四、单批次生成顺序

1. 核验当年通知和模板，确定`package_scope`。
2. 冻结项目主清单快照；全部材料只从同一快照取题目、人员、日期、术语和成果名称。
   - 按`project-intake.example.json`建立一次采集信息，运行`initialize_project_package.py`创建26项生命周期主清单、标准目录、注意事项、交付索引和XLSX草稿；初始化文件保持`draft`直至完成视觉与内容QA。
   - 只有基本情况时，先用`project_workflow.py start`生成5—8项候选；用户只需确认一个候选ID。随后用`select`和`initialize`子命令生成主清单与材料任务计划。
3. 先生成承诺、逻辑矩阵、变量编码和时间轴，再生成各份正文。
4. 先生成可执行工具和工作簿，再生成分析报告骨架；没有真实数据时不得填结果。
5. 教案、任务单、量规和案例共用同一目标—任务—成果—评价映射。
6. 根据主学科加载专项真实证据、安全、伦理和版权要求；跨学科时只加载实际关联学科，并分别登记核验人/来源。
   - 主学科及每个关联学科都必须进入`subject_coverage`，分别写清研究功能、课标/教材范围、工具、证据和复核人；未登记的“跨学科”不得进入实施稿。
7. 根据关键研究节点和学科特点生成照片拍摄清单，并在工作版中写入结构化照片ID备注；真实照片到位后批量替换、生成图题和证据册，报送/公开终稿不得残留待插图备注；照片不能替代录音、作品版本、原始测量、代码日志或量规评分。
8. 按材料用途制作`working/submission/anonymous/public`版本；签章材料保留真人填写区。
9. 从同一主清单生成根目录`00_课题材料包注意事项_真实性与待办清单.docx`，详细汇总缺失照片、原始材料、学科专项证据与风险、签章、时间冲突、阶段待办和增强建议，并将该文件登记为ready。
10. 运行生命周期覆盖审计和一键预检；逐页渲染所有DOCX/PDF，逐表渲染所有XLSX。
11. 输出材料目录、状态、缺失真实证据和下一次批量刷新入口。

初始化不等于成套生成完成。初始化后读取`material-generation-plan.json`，反复处理`next_jobs`、登记文件并刷新计划。每个任务都必须满足内容合同、格式母版和QA门槛；缺少官方模板的`official-exact`任务进入`blocked-template`，不能用通用母版冒充。没有未来数据或照片的结果型材料仍要生成结构完整的可填写工作稿，但保持相应待办状态。

任何上游字段修改，先更新主清单，再用`plan_incremental_refresh.py`比较父子快照，整体重生受影响文件；不得手工逐文件改题目、日期或样本量。生成后的文件用`register_material_file.py`登记哈希和状态；`ready`必须绑定真实QA记录。

## 五、可用状态的准确含义

- `application-scaffold`：申请材料目录和官方表格待办已建立，尚未完成当年格式/内容/签章门槛。
- `application-ready`：申报内容和当年格式可报送，真人签章事项除外。
- `implementation-scaffold`：实施材料角色已建立，至少一项工具、编码、伦理或载体仍未完成可执行QA。
- `implementation-ready`：工具、表格、课例和台账可以直接实施/打印/录入。
- `closing-scaffold`：已有真实结题输入或已建立结题配方，但数据、照片、证明、格式或签章仍待补。
- `closing-ready`：真实数据、照片、成果和批准信息已进入，结题模板和全套审计通过。
- `full-lifecycle-scaffold`：生命周期材料齐全，但未来事实型材料按状态待补；不能称为整套结题终稿。

交付时必须使用以上受控状态之一，禁止含糊使用“全部可用”。

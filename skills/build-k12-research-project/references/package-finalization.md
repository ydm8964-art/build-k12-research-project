# 整套材料终稿与文件夹验收

本文件用于把单份“看起来完成”的文件变成可提交、可复核、可归档的整套材料。

## 一、交付目录与索引

最终包保留一个项目主清单和一份交付索引。每份材料登记材料ID、正式名称、相对路径、格式、版本、SHA-256、隐私等级、是否必交、负责人、数据截止日期、依赖、当前状态和各项审计结果。

主清单另存“当年要求快照”：管理单位、年度、核验日期、截止日期、通知和模板来源ID、必交材料ID、匿名要求、提交方式以及文件名/大小/份数规则。快照状态只能为`pending/verified/expired`；新年度通知发布、管理单位变更或附件更新后，旧快照改为`expired`并重新核验。

文件名使用`序号_材料名称_版本或日期.ext`，避免“最终版2、最新版、修改版、复件、(1)”等无法追溯命名。工作稿、原始敏感数据和公开交付包分目录保存，不把`~$`临时文件、缓存、渲染PNG或系统隐藏文件交付。

## 二、材料状态门槛

建议状态：`planned`、`draft`、`pending-data`、`pending-photo`、`pending-signature`、`verified`、`ready`、`submitted`、`archived`。

只有满足以下条件才标记`ready`：

- 文件实际存在、能打开、扩展名与登记格式一致，哈希已登记；
- 内容、格式、渲染、隐私和数据审计均为`passed`或明确`not-applicable`；
- 每个`passed`状态均有`qa_records`，记录核验日期、方法、报告路径或审阅人；不得仅在JSON里手工写成通过；
- 必要真实数据、照片、来源和证据已经补齐；
- 无待填写、待确认、待插图、旧项目残留、批注、修订、隐藏文字和错误外部链接；
- 目录、页码、图表题注和交叉引用更新；
- 签字盖章等确需线下完成的事项单独标为`pending-signature`，不得假造。

## 三、DOCX终稿清理

- 接受或拒绝全部修订，移除批注、隐藏文字、模板说明和工作备注；
- 清理作者、最后修改者、自定义属性和无关修订会话信息；
- 检查外部链接、外链图片、域代码、目录、页码、题注和交叉引用；
- 检查纸张、分节、页眉页脚、空白页、表格越界、字体替换和图片清晰度；
- 匿名/公开版再次扫描身份信息和图片人物；
- 渲染全部页面，逐页通过后再生成PDF。

官方模板需要保留的域、内容控件或签章位置不能因“清理”被删除。先制作副本，再执行清理和比对。

## 四、XLSX终稿清理

- 不含未说明的隐藏工作表/行列、外部工作簿链接、宏、错误公式和临时模拟数据；
- 所有公式范围、数据验证、保护、筛选、冻结窗格和打印区域可用；
- 原始数据、清理数据和分析结果分层，敏感映射表不进入普通交付包；
- Word/PDF中的表图与工作簿数据截止日期、N值和精度一致；
- 逐工作表渲染检查，不把计算底稿误当作公开附件。

## 五、PDF终稿清理

- PDF页数与最终DOCX一致，页面方向、字体、图片、表格和签章清晰；
- 文字型材料应可检索；扫描原件说明来源，必要时OCR但不改变签章图像；
- 不加密到管理部门无法打开，不保留无关批注、附件或脚本；
- 按要求合并或拆分，核对书签、页码、文件大小和打印效果；
- PDF只是定稿载体，仍保留可编辑DOCX/XLSX和真实原始数据。

手写问卷、访谈和观察扫描件应完整保留页边、页序和原始笔迹，并按记录ID建立页码索引。扫描件没有文本层时，可另做经复核的转写/OCR副本，但不能覆盖原扫描件；转写保留“原页码—记录ID—转写文本—复核人”。文件名必须区分“空白提纲/表”“已填写原件”“转写稿”和“分析报告”，不能把多份填写记录仍命名为“提纲”。

## 六、承诺、依赖和证据验收

- 必交材料全部存在；申请书承诺的成果逐项为`fulfilled/changed-approved/not-fulfilled`；
- 下游材料引用的上游版本已冻结，题目、人员、数据、日期和成果名称一致；
- 已证实结论均能定位到证据ID和实际文件；实施案例有日期、班级、教师和证据；
- 材料宣称含照片、附录、量规、任务单或证明时，文件包中确实存在；
- 变更、延期、外部协作者、成果署名和未兑现事项均有说明。

## 七、机器审计与人工终审

正式交付运行一键预检并保存JSON报告：

```bash
python scripts/run_project_preflight.py project-manifest.json --root delivery-folder --final --report-json preflight-report.json
```

一键预检实际调用主清单、文件夹、DOCX内容、DOCX格式、XLSX结构/公式、案例和照片审计，检查缺件、路径、格式、哈希、状态、承诺、依赖、占位符、批注/修订/外链、必需工作表、公式错误、筛选/冻结窗格及PDF基本可用性。单项脚本只用于问题定位。机器通过后仍需人工逐页查看、核对数据计算、照片授权、学科事实、签章和实际报送系统要求，并在`qa_records`留痕。

最终交付附四项：材料目录与状态、当年要求快照、预检报告、`00_课题材料包注意事项_真实性与待办清单.docx`。注意事项文件必须从当前主清单自动重建，区分当前阻断、必须补充、阶段待办和建议增强，并列清真实照片、原始记录/数据、主学科及关联学科专项证据/风险、证明、签章和时间逻辑。任何当前阻断项未清零，或警告未处置时，不使用“整套可直接提交”。

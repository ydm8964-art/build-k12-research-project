# 材料包注意事项与真实性待办文件

每次生成课题材料包时，在根目录同步生成`00_课题材料包注意事项_真实性与待办清单.docx`。该文件是交付给教师/负责人使用的控制文件，不代替管理部门要求的官方材料，默认不上传申报或结题系统。

## 一、生成原则

1. 只从同一项目主清单、材料状态、证据登记和时间轴生成，不凭空增加已经发生的事实。
2. 每次批量生成或上游事实变化后重建；不得手工保留已经解决的旧待办。
3. 明确区分：
   - `当前阻断`：不解决就不能达到本批次目标状态；
   - `必须补充`：相应阶段到来前必须取得的真实材料；
   - `阶段待办`：未来活动或结果尚未发生，按计划准备；
   - `建议增强`：不是硬性缺件，但能明显改善证据链或评审说服力。
4. 每条事项写明原因、取得方式、责任人、最迟时间、对应材料ID和完成标准，不能只列“补照片、补数据”。
5. 注意事项文件本身可以标记`ready`，但其中的阻断项是否清零决定整套材料能否标记`application-ready/implementation-ready/closing-ready`。

## 二、固定结构

### 1. 材料包状态快照

- 课题题目、负责人、单位、项目阶段；
- 成套范围、真实性阶段、目标交付状态、数据截止日期；
- 当年通知/模板核验状态；
- 当前阻断、必须补充、阶段待办和建议增强的数量。

### 2. 缺失、矛盾与待人工完成事项

至少包含：事项ID、级别、类别、具体问题、为什么需要、建议行动、责任人、最迟时间、对应材料/证据、完成标准和状态。

重点自动汇总：

- 未取得或未核验的当年通知、指南、官方Word/PDF/Excel附件；
- 教师、学校、成员、编号、样本、教材版本等尚未确认的关键事实；
- 未取得的签字、盖章、专家意见、单位意见和审批；
- 未回收的问卷、访谈原件/录音/转写、观察记录、测评、学生作品和量规评分；
- 缺失的原始数据、编码本、XLSX录入、统计结果和数据截止日期；
- 未取得的立项、开题、中期、变更、延期、获奖、发表、应用和推广证明；
- 已承诺但尚未形成或尚未获批变更的成果；
- 开发案例被误写为实施案例、效果结论缺证据或署名/授权不完整等问题。

### 3. 真实照片拍摄、提供与插入清单

每条照片任务至少包含：照片ID、研究阶段、真实活动/建议画面、必须同时取得的信息、人物授权/打码要求、目标材料和插入位置、最迟取得时间及状态。

没有用户真实照片时，只生成拍摄/提供任务，不嵌入网络图、AI图或其他项目照片。建议优先覆盖：研究准备或集体研讨、工具预测试/调查、课堂策略实施、学生任务过程、学生作品、评价反馈、反思改进、成果应用或推广。不是每个项目都强制全部类型，不适用的照片任务应删除或写明理由。

### 4. 其他真实原始材料清单

按“官方与审批、研究伦理、工具与原始记录、课堂与学生成果、过程管理、数据与分析、成果与推广、签章”分类，写明原件最低标准、文件命名、保存目录、对应时间和用途。扫描件、录音、照片及电子数据保留原件；OCR、转写、压缩、打码或统计副本不得覆盖原件。

### 5. 学科专项真实性与安全核验

根据项目主清单中的主学科自动加载[subject-specific-evidence.md](subject-specific-evidence.md)的对应行，至少列出：学科/领域、应取得的真实材料、学习或效果证据、关键学科事实、安全/伦理/版权要求、对应材料与完成标准。跨学科课题同时列主学科和实际涉及的关联学科；未知学科使用通用底座并提示负责人补充，禁止把某一个学科的证据模式机械套用到全部学科。

照片任务也要按学科调整：实验学科强调原始测量与安全，语言学科强调作品修改和听说证据，艺体学科强调过程/展演/动作量规及授权，信息科技强调源文件/版本日志/截图，政史地强调权威来源，心理健康强调敏感信息最小化。照片不能替代测评、录音、代码、作品版本、实验数据或量规评分。

### 6. 时间逻辑检查

固定检查：

- 前期基础 → 申报 → 立项 → 开题；
- 工具设计 → 预测试 → 正式采集 → 清理/编码 → 分析；
- 诊断 → 干预设计 → 实施 → 评价 → 中期/总结；
- 成果形成 → 最终研究报告 → 结题申请/鉴定；
- 照片、观察、教学反思、学生作品和量规日期是否与同一课例一致；
- 当前日期晚于计划节点时，相应真实材料是否已经登记；
- 延期、题目、成员、周期或成果变更是否有批准依据。

时间表至少列出计划日期、实际日期/证据、前置条件、检查结果、处理建议和最迟完成时间。不能通过倒改日期解决冲突；立项前真实活动应标注为前期调查/预研究。

### 7. 建议增加的增强材料

按优先级列出可选增强项及理由，例如：预测试与修订记录、对照/前后测、学生作品量规、反例记录、实施保真度、集体备课记录、家长/学生告知同意、应用证明、使用反馈、成果推广、数据字典、原件哈希清单。建议项必须与课题方法和结论有关，不为凑数量堆材料。

### 8. 教师最终操作顺序

按时间先后列出下一步行动，默认顺序为：核验官方要求 → 确认身份和时间 → 准备伦理/工具 → 采集原始数据和照片 → 整理编码 → 形成分析 → 实施与评价 → 补齐过程/成果证明 → 真人签章 → 全套预检与上传。

## 三、状态与交付门槛

- `full-lifecycle-scaffold`允许文件中保留阶段待办，但必须把未来数据、照片和签章写清楚。
- `application-ready`不得保留影响申报资格、官方格式、匿名和必交附件的当前阻断项。
- `implementation-ready`不得缺少可直接使用的工具、编码、数据台账、伦理文件、策略载体和照片/过程记录计划。
- `closing-ready`不得仍有待数据、待照片、待成果证明或待批准变更；确需线下签章的事项按管理部门规则处理，但不得伪造。

注意事项文件完成后登记为`material_role=attention-items`、`format_profile=attention-items`、`privacy_class=internal`，并进入交付索引和一键预检。

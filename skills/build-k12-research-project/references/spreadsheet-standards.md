# 课题电子表格格式规范

## 一、工作簿在整套材料中的位置

电子表格是问卷、访谈、观察、评价、证据和材料进度的可追溯底稿。Word分析报告中的数字必须来自工作簿公式或已核验汇总，不得在Word中手工另算一套。

## 二、推荐工作簿组成

没有当年官方电子表格时，优先复制`assets/templates/project-data-workbook.xlsx`。如需重建，先通过Codex工作区依赖加载器取得Node和`node_modules`路径，在可写临时目录同时放置`build_generic_xlsx_template.mjs`与`normalize_xlsx_views.py`并建立`node_modules`符号链接，再运行`node build_generic_xlsx_template.mjs 输出路径.xlsx`；主脚本使用公开包入口`@oai/artifact-tool`，兼容脚本只补足导出器未物化的标准冻结窗格，不猜测运行时内部文件路径。该文件是通用研究数据底稿，不是官方申报附件；实际字段、量表和报送列仍按项目主清单与当年要求调整。

项目主清单已经建立时，使用`populate_project_workbook.mjs --input 母版.xlsx --output 项目工作簿.xlsx --manifest project-manifest.json --qa-dir 逐表预览`自动写入项目说明、证据索引、照片登记和材料进度。脚本只同步登记事实，不制造问卷回收、测评分数或分析结果；输出后继续执行结构审计并人工查看9张预览图。

根据研究方法选用，不需要的工作表可以不建：

| 工作表 | 用途 | 关键字段/要求 |
|---|---|---|
| 项目说明 | 项目身份、版本、统计口径、填表说明 | 题目、负责人、学校、研究周期、数据更新时间、匿名规则 |
| 变量编码 | 问卷和量表代码本 | 变量名、题号、维度、题型、选项代码、缺失值、计分方向 |
| 问卷原始数据 | 一行一个有效答卷，一列一个变量 | 匿名ID、时间、对象组别、Q01…Qn；只保留原始输入 |
| 数据清理 | 由原始数据派生的清理结果 | 保留原值、清理值、问题标记、排除理由；不覆盖原始表 |
| 访谈编码 | 访谈主题和证据索引 | 访谈ID、日期、对象类型、主题码、摘要、原文位置 |
| 课堂观察 | 一行一次观察或一个维度记录 | 观察ID、日期、教师编码、班级、维度、等级、叙事记录 |
| 前后测/作品评价 | 学生层面效果数据 | 匿名学生ID、组别、测次、维度分、总分、缺失标记 |
| 统计分析 | 频数、比例、均值、交叉/前后对比 | 全部由公式引用数据表，写明N值和口径 |
| 图表结果 | Word报告需要的最终表图 | 只放经过核验的结果；图表标题和单位完整 |
| 证据索引 | 关联原件、照片、作品和分析 | 证据ID、类型、日期、是否随包、交付相对路径或受控保管责任人/定位/核验日期、哈希、对应问题/材料/结论、隐私状态 |
| 照片登记 | 管理真实照片原件、授权、图题和插入位置 | 照片ID、原文件名、SHA-256、日期、地点、活动、来源、是否随包、原件相对路径或受控保管记录、授权、人物处理、图题、替代文本、对应材料/案例/图号、派生文件 |
| 材料进度 | 管理整套材料 | 材料ID、名称、负责人、计划/实际日期、状态、依赖、文件路径 |

## 三、原始数据硬规则

- 一行一条记录，一列一个变量；首行唯一字段名，不使用多行表头。
- 数据区不合并单元格，不插入小计行，不用空行分组。
- 数字、日期、百分比保存为相应数据类型；学生编号、题号等标识保存为文本。
- 不以颜色作为唯一信息，另设`状态`、`缺失原因`、`异常标记`等字段。
- 使用匿名ID，学生姓名和敏感信息不进入分析工作簿；确需对应表时单独加密保存。
- 原始数据工作表只追加和纠错留痕，不进行覆盖式清洗。
- 原始照片与派生照片分开；照片登记表保留原件哈希和处理记录，不在普通XLSX中嵌入大量原图。

## 四、编码与公式

- 题号使用稳定代码，如`T_Q01`、`S_Q01`；选项编码在变量编码表中可见。
- 单选和量表用数据验证限制输入；多选题可拆成0/1变量，不把“A,C,D”作为唯一可分析结构。
- 反向题在编码表中标明，转换在数据清理表中用公式完成。
- 频数、比例、有效率、均值和评价总分使用公式，不把计算结果硬编码。
- 跨工作表公式始终写成`='工作表名'!A1`形式；使用有限范围，避免整列引用。
- 百分比保存为小数并设置`0.0%`或所需精度；频数设置为整数。
- 对除数为0、空值和非法代码设置可解释处理，终稿不得出现公式错误。

## 五、可用性格式

M09的具体字体、字号、颜色、行高、冻结位置和工作表顺序以[26项材料固定版式合同](material-format-contracts.md)及其JSON执行源为准；填充数据不得改变母版样式。生成后运行`audit_xlsx_style_contract.py`与固定母版逐表比对。

- 冻结首行或关键标识列；大型数据表开启筛选。
- 标题、表头、输入、公式和异常状态有一致但克制的视觉区分。
- 列宽按内容设置，长文本列换行；避免无限加宽或行高过度膨胀。
- 输入区可使用浅色提示，公式区避免随意覆盖；必要时保护公式单元格。
- 日期统一`yyyy-mm-dd`，计数`#,##0`，比例`0.0%`，分数按量规精度设置。
- 不格式化大量未使用行列，不保留默认空白工作表。
- 打印用汇总表设置打印区域、重复标题行、页眉页脚和适合纸张；原始数据表以屏幕录入为主，不强求打印成一页。

## 六、Word与Excel同步

建立“表图登记表”：Word中的表号/图号、Excel来源工作表和区域、统计口径、生成日期、复核人。数据修改后，标记所有受影响的Word分析报告并重新导出表图。

Word三线表可由Excel核验结果生成，但必须保持数值和精度一致。不要截图粘贴可编辑数据表；需要保留计算能力时提供XLSX，需要排版时在Word中重建规范表格并保留来源区域。

照片登记表同时维护Word图号和照片ID。增删照片后更新图号、对应页码和材料位置；Word图题、PDF页面、登记表日期/活动必须一致。

## 七、电子表格验收门槛

1. 检查关键区域的值和公式，抽查频数与比例。
2. 扫描`#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`和`#N/A`。
3. 核对样本总数、有效数、多选题分母、前后测匹配数和量规权重。
4. 渲染并查看每个工作表，确保标题、表头、数字和图表不被截断。
5. 检查筛选、冻结窗格、数据验证、条件格式和打印区域是否可用。
6. 导出XLSX后重新打开检查；只有计算、结构和视觉均通过才标记“可直接使用”。
7. 运行`audit_xlsx_style_contract.py M09.xlsx`，确认字体字号、颜色、行高、列宽、冻结窗格、网格线及第1—33行预留区样式未漂移。
